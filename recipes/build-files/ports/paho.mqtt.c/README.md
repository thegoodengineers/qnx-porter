# paho.mqtt.c for QNX 8.0

Generated by [qnx-porter](https://github.com/thegoodengineers/qnx-porter) from its automatic port of
paho.mqtt.c `v1.3.14` (https://github.com/eclipse/paho.mqtt.c.git). On a QNX 8.0 x86_64 target (QEMU) its test suite did not run there (see the port's report). Full report:
`ports/paho.mqtt.c/REPORT.md` in qnx-porter.

## Build
```bash
source ~/qnx800/qnxsdp-env.sh
git clone --depth 1 --branch v1.3.14 https://github.com/eclipse/paho.mqtt.c.git paho.mqtt.c
git -C paho.mqtt.c apply ../build-files/ports/paho.mqtt.c/qnx.patch
QNX_PROJECT_ROOT="$(pwd)/paho.mqtt.c" make -C build-files/ports/paho.mqtt.c install JLEVEL=4
```

## QNX changes, each with its reason
| rule | reason |
|---|---|
| bool-typedef | src/MQTTPacket.h defines its own `bool`, but on QNX 8.0 <sys/socket.h> already includes <stdbool.h> (via io-sock/types_fbsd.h), so `bool` is taken. The typedef is skipped when stdbool's bool is visible. Note: bool is then _Bool, not unsigned int, in those files. |
| link-libsocket | `recv` is in QNX's libsocket, not in libc as on Linux: link with -lsocket. |
| endian-netbyte | `be32toh` comes from glibc's <endian.h>, which QNX 8.0 does not have. QNX has the same names as BSD macros in <net/netbyte.h>; a small header (-included in every compile) includes it and defines any name strict POSIX flags hid, from QNX's __NET_BE*/__NET_LE* helpers. |

Compat headers in `qnx-compat/` (qnx-endian.h) are `-include`d by common.mk.
