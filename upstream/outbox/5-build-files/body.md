Adds a port of [yyjson](https://github.com/ibireme/yyjson) 0.10.0, which has no build files or repository in qnx-ports yet.

**What is in it**
- `ports/yyjson/`: the usual layout (`Makefile`, `common.mk`, `qnx.nto.toolchain.cmake`, `nto-x86_64-o/`, `nto-aarch64-le/`) and a `README.md` with build steps. yyjson builds from the upstream tag; no source patch and no fork are needed.
- `.github/workflows/yyjson.yml`: build workflow in the same shape as `cJSON.yml` (checks out `ibireme/yyjson` at `0.10.0`, then `make -C build-files/ports/yyjson install`).
- One row in the port table in `README.md`.

**The one QNX change:** link with `-lm`. QNX's `<math.h>` implements `isinf`/`isfinite`/`isnan` as calls to `__isinf` and friends in libm, where glibc needs no library.

**Choices that differ from some existing ports**
- Static library by default (`BUILD_SHARED_LIBS ?= OFF`), as it was tested; set it to `ON` for a shared one.
- `common.mk` writes empty `librt.a`, `libdl.a` and `libpthread.a` archives into the build folder, because QNX keeps those functions in libc and some CMake checks insist on finding the libraries.
- The toolchain file names the archiver `nto<cpu>-ar` without the trailing `le` (`ntoaarch64-ar`), which a static aarch64 build needs.

**How it was tested**
- yyjson 0.10.0 built with these settings on QNX SDP 8.0 and its own test suite ran on a QNX 8.0 x86_64 target (QEMU): 12/12 tests passed.
- These build files, with QNX's recursive make (`make install` with `INSTALL_ROOT_nto` set to a staging folder) from a fresh clone of the `0.10.0` tag: built and installed `libyyjson.a` and its header for `nto-x86_64-o` (13 Nov 2026), and built for `nto-aarch64-le` earlier.
- Not tested: the workflow itself (it needs your runner and SDP), and yyjson's tests on an aarch64 target with these build files.
