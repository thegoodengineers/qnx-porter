Adds a port of [Mbed TLS](https://github.com/Mbed-TLS/mbedtls) v3.6.2, which has no build files or repository in qnx-ports yet.

**What is in it**
- `ports/mbedtls/`: the usual layout (`Makefile`, `common.mk`, `qnx.nto.toolchain.cmake`, `nto-x86_64-o/`, `nto-aarch64-le/`) and a `README.md` with build steps. Mbed TLS builds from the upstream tag (with its `framework` submodule); no source patch and no fork are needed.
- `.github/workflows/mbedtls.yml`: build workflow in the same shape as `cJSON.yml` (checks out `Mbed-TLS/mbedtls` at `v3.6.2` with submodules, then `make -C build-files/ports/mbedtls install`).
- One row in the port table in `README.md`.

**The one QNX change:** link with `-lsocket`. `inet_pton` is in QNX's libsocket, not in libc as on Linux. `ENABLE_PROGRAMS` is off.

**Choices that differ from some existing ports**
- Static libraries by default (`BUILD_SHARED_LIBS ?= OFF`), as tested; set it to `ON` for shared ones.
- `common.mk` writes empty `librt.a`, `libdl.a` and `libpthread.a` archives into the build folder, because QNX keeps those functions in libc and some CMake checks insist on finding the libraries.
- The toolchain file names the archiver `nto<cpu>-ar` without the trailing `le` (`ntoaarch64-ar`), which a static aarch64 build needs.

**How it was tested**
- Mbed TLS v3.6.2 built with these settings on QNX SDP 8.0 and its own test suites ran on a QNX 8.0 x86_64 target (QEMU): 130/130 passed.
- These build files, with QNX's recursive make (`make install` with `INSTALL_ROOT_nto` set to a staging folder) from a fresh `--recurse-submodules` clone of `v3.6.2`: built and installed `libmbedtls.a`, `libmbedx509.a`, `libmbedcrypto.a` (plus `libeverest.a`, `libp256m.a`) and the headers for `nto-x86_64-o` (13 Nov 2026).
- Not tested: `nto-aarch64-le` through these build files, and the workflow itself (it needs your runner and SDP).
